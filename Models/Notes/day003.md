# Day 3 - The Model Learns

## Objective

Teach the model how to improve its own parameter instead of manually changing it.

---

## What we built

We built our first self-improving learning model.

Unlike the previous model, this one repeatedly:

1. Makes a prediction.
2. Calculates its error.
3. Adjusts its weight.
4. Makes another prediction.
5. Repeats until the prediction is close enough.

For the first time, the computer improved its own parameter without my intervention.

---

## Concepts Learned

### Error

Error tells us:

prediction - actual

Unlike loss, error still contains direction.

Example:

Prediction = 16
Actual = 4

Error = +12

Prediction = -8
Actual = 4

Error = -12

Positive and negative errors tell us whether we overshot or undershot.

---

### Loss

Loss measures how wrong the prediction is.

We used:

loss = error²

Squaring makes every loss positive.

Example:

Error = +12 → Loss = 144

Error = -12 → Loss = 144

Loss tells us how bad the prediction is.

Loss does NOT tell us which direction to move.

---

### Learning Rate

Instead of changing the weight by a huge amount, we change it by a tiny amount.

Example:

learning_rate = 0.001

Large learning rate:

- Can overshoot the correct value.
- Can become unstable.

Very small learning rate:

- Learns correctly.
- Takes much longer.

Learning rate is similar to pressing the accelerator while parking a car.

---

### Floating Point Numbers

Computers store decimal numbers in binary.

Some decimal numbers (like 0.1) cannot be represented exactly.

Example:

Instead of:

4.1

the computer may store:

4.099999999999775

This is normal.

Because of this, machine learning usually checks:

abs(error) > tolerance

instead of:

error == 0

---

## Our First Learner

Algorithm:

Start

↓

Predict

↓

Calculate error

↓

If prediction is too high

    decrease weight

Else

    increase weight

↓

Repeat until error is small

---

## Limitation of Our Learner

Our learner works because our model is:

prediction = x × w

In this model:

Increasing w always increases prediction.

Decreasing w always decreases prediction.

This assumption breaks for models like:

prediction = w² × x

or

prediction = sin(w) × x

because changing w does not always change the prediction in the same direction.

---

## Why This Matters

Our learner is hardcoded to move left or right based on the sign of the error.

It is NOT a general solution.

We need mathematics that works for any equation.

That mathematics is called the derivative.

## Questions I Asked Myself

1. Why use error instead of loss?
   Because error still tells us the direction.

2. Why not use a huge learning rate?
   Because it can overshoot the best solution.

3. Why don't we compare floating point numbers with zero?
   Because decimal numbers cannot always be represented exactly.

4. Will this learner work for every mathematical model?
   No.
