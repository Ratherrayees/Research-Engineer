# Tensors & Data — Day 3

## Tensor Operations and Shape Manipulation: Element-Wise Math, Broadcasting, Reshape, View, Flatten, Squeeze, and Unsqueeze

---

## 1. Two Families of Tensor Operations

By this point, tensor structure is familiar:

```text
shape
axes
indexing
slicing
```

The next step is to distinguish two broad kinds of operations.

### Mathematical operations

These calculate with the values:

```text
+
-
*
/
@
```

### Structural operations

These reorganize how the same values are arranged:

```text
reshape
view
flatten
squeeze
unsqueeze
```

This distinction is important because changing a tensor's shape is not the same as changing its numerical values.

---

## 2. Element-Wise Operations

Element-wise operations work position by position.

Suppose:

```python
import torch

A = torch.tensor([
    [1.0, 2.0],
    [3.0, 4.0]
])

B = torch.tensor([
    [5.0, 6.0],
    [7.0, 8.0]
])
```

Element-wise addition:

```python
print(A + B)
```

means:

```text
1 + 5
2 + 6
3 + 7
4 + 8
```

Result:

```text
[[ 6,  8],
 [10, 12]]
```

Element-wise multiplication:

```python
print(A * B)
```

means:

```text
1 × 5
2 × 6
3 × 7
4 × 8
```

Result:

```text
[[ 5, 12],
 [21, 32]]
```

The positions interact with their corresponding positions.

---

## 3. Element-Wise vs Matrix Multiplication

This distinction must remain clear:

```text
A * B
→ element-wise multiplication

A @ B
→ matrix multiplication
```

Even if two square matrices have the same shape, these are completely different calculations.

Matrix multiplication will be studied in detail on Day 4.

---

## 4. Why Element-Wise Operations Matter in AI

One real use is applying masks or scales.

Suppose:

```text
values =
[
  [0.8, 0.3, 0.9],
  [0.5, 0.7, 0.2]
]
```

and a simple mask is:

```text
mask =
[
  [1, 1, 0],
  [1, 0, 0]
]
```

Element-wise multiplication gives:

```text
[
  [0.8, 0.3, 0.0],
  [0.5, 0.0, 0.0]
]
```

The operation acts independently at matching positions.

---

## 5. Broadcasting

Element-wise operations usually need compatible shapes.

Broadcasting allows a smaller tensor to participate in an operation with a larger tensor without manually copying it across every position.

Example:

```python
import torch

A = torch.tensor([
    [10.0, 20.0, 30.0],
    [40.0, 50.0, 60.0]
])

b = torch.tensor([1.0, 2.0, 3.0])

result = A + b

print(result)
```

Result:

```text
[[11, 22, 33],
 [41, 52, 63]]
```

The vector `b` is reused for every row.

---

## 6. Broadcasting Compares Shapes from the Right

For:

```text
A.shape = (2, 3)
b.shape =    (3,)
```

align the shapes from the right:

```text
(2, 3)
(   3)
```

Conceptually, the missing dimension can be treated as size `1`:

```text
(2, 3)
(1, 3)
```

Then compare each aligned dimension.

---

## 7. Broadcasting Compatibility Rule

Two aligned dimensions are compatible if:

```text
they are equal
OR
one of them is 1
```

Example:

```text
(8, 20, 64)
(1,  1, 64)
```

Compare:

```text
8  vs 1   → compatible
20 vs 1   → compatible
64 vs 64  → compatible
```

Result shape:

```text
(8, 20, 64)
```

The size-1 axes can be reused across the larger dimensions.

---

## 8. Broadcasting Does Not Mean Arbitrary Resizing

Suppose:

```text
A.shape = (2, 3)
B.shape = (2,)
```

Align from the right:

```text
(2, 3)
(   2)
```

The final dimensions are:

```text
3 vs 2
```

They are not equal, and neither is `1`.

So broadcasting fails.

The rule is strict; PyTorch is not simply stretching tensors however it wants.

---

## 9. Neural-Network Bias and Broadcasting

Suppose a neural-network computation produces:

```text
output.shape = (32, 50, 3072)
```

and the layer has a bias vector:

```text
bias.shape = (3072,)
```

Then:

```python
output = output + bias
```

works because the bias aligns with the final feature dimension.

Conceptually:

```text
(32, 50, 3072)
( 1,  1, 3072)
```

The same 3072 bias values are reused for every token in every sample.

This is one of the most important real uses of broadcasting.

---

## 10. Reshape

`reshape` changes how the same values are organized.

It does not perform mathematical calculations on the values.

Example:

```python
import torch

x = torch.tensor([1, 2, 3, 4, 5, 6])

y = x.reshape(2, 3)

print(y)
```

Result:

```text
[[1, 2, 3],
 [4, 5, 6]]
```

The values are still:

```text
1, 2, 3, 4, 5, 6
```

Only the structure changed.

---

## 11. Golden Rule of Reshaping

The total number of elements must remain unchanged.

Suppose:

```text
x.shape = (8, 20, 64)
```

Total elements:

```text
8 × 20 × 64 = 10,240
```

These are valid reshapes:

```text
(160, 64)   → 160 × 64 = 10,240
(8, 1280)   → 8 × 1280 = 10,240
(10240,)     → 10,240
(10, 1024)   → 10 × 1024 = 10,240
```

This is invalid:

```text
(40, 200) → 8,000
```

because PyTorch cannot destroy 2,240 values just to satisfy the requested shape.

---

## 12. Reshape Does Not Mean the Resulting Computation Is the Same

Reshaping does not change the values by itself.

But a later operation may interpret the reorganized structure differently.

So:

```text
reshape
→ does not numerically change values
```

but:

```text
reshape
→ may change which values interact in a later operation
```

This is why wrong shapes can produce wrong model behavior even when the tensor contains the correct numbers.

---

## 13. Automatic Dimension Inference with `-1`

PyTorch can infer one dimension automatically.

```python
x = torch.arange(24)

y = x.reshape(4, -1)

print(y.shape)
# torch.Size([4, 6])
```

PyTorch solves:

```text
4 × ? = 24
```

so:

```text
? = 6
```

Another example:

```python
y = x.reshape(2, 3, -1)
```

PyTorch solves:

```text
2 × 3 × ? = 24
```

therefore:

```text
? = 4
```

Only one dimension can normally be inferred, because two unknown dimensions would be ambiguous.

---

## 14. `view()`

PyTorch also provides:

```python
x.view(...)
```

For many simple tensors, this appears to behave like `reshape`.

```python
x = torch.tensor([1, 2, 3, 4, 5, 6])

y = x.view(2, 3)
```

The important intuition is:

> `view()` tries to reinterpret the same underlying memory using a different shape.

Conceptually:

```text
memory:
1 2 3 4 5 6

view(2, 3):
[[1, 2, 3],
 [4, 5, 6]]
```

`view()` is stricter about memory layout.

---

## 15. `reshape()` vs `view()`

A useful beginner mental model is:

```text
view()
→ reinterpret existing memory when the layout permits it

reshape()
→ give me this shape; reuse memory if possible, otherwise handle what is necessary
```

This distinction becomes clearer later when contiguous memory is studied.

For now, `reshape()` is usually the more forgiving default when simply learning shape transformations.

---

## 16. Flatten

Flattening combines dimensions together.

Example:

```python
x = torch.tensor([
    [1, 2, 3],
    [4, 5, 6]
])

print(x.shape)
# torch.Size([2, 3])

y = x.flatten()

print(y.shape)
# torch.Size([6])
```

Result:

```text
[1, 2, 3, 4, 5, 6]
```

So:

```text
(2, 3)
↓ flatten
(6,)
```

---

## 17. Flattening While Keeping the Batch Axis

Suppose image data has shape:

```text
(32, 3, 224, 224)
```

meaning:

```text
32  images
3   channels
224 height
224 width
```

If each image must become one long vector while keeping the 32 images separate:

```python
x = torch.randn(32, 3, 224, 224)

y = x.flatten(start_dim=1)

print(y.shape)
# torch.Size([32, 150528])
```

because:

```text
3 × 224 × 224 = 150,528
```

So:

```text
(32, 3, 224, 224)
 ↓ keep batch
(32, 150528)
```

If everything were flattened, the distinction between separate images would be lost.

---

## 18. Why Size-1 Axes Matter

A dimension whose size is `1` may look useless, but it can carry structural meaning.

Suppose one sample has:

```text
(64,)
```

A model expects:

```text
(batch, features)
```

Then the single sample should be represented as:

```text
(1, 64)
```

The `1` means:

```text
one sample in the batch
```

---

## 19. `unsqueeze()`

`unsqueeze()` inserts a new axis of size `1`.

```python
x = torch.randn(64)

print(x.shape)
# torch.Size([64])

print(x.unsqueeze(0).shape)
# torch.Size([1, 64])

print(x.unsqueeze(1).shape)
# torch.Size([64, 1])
```

The argument tells PyTorch where to insert the new axis.

For:

```text
(8, 20, 64)
```

we get:

```text
unsqueeze(0) → (1, 8, 20, 64)
unsqueeze(1) → (8, 1, 20, 64)
unsqueeze(2) → (8, 20, 1, 64)
unsqueeze(3) → (8, 20, 64, 1)
```

---

## 20. `unsqueeze(-1)`

Negative axis numbers count from the end.

So:

```python
x.unsqueeze(-1)
```

adds a new final axis.

For:

```text
(8, 20, 64)
```

this produces:

```text
(8, 20, 64, 1)
```

---

## 21. `squeeze()`

`squeeze()` removes axes whose size is exactly `1`.

```python
x = torch.zeros(1, 20, 1, 64, 1)

y = x.squeeze()

print(y.shape)
# torch.Size([20, 64])
```

All size-1 axes were removed.

A specific axis can be requested:

```python
x = torch.zeros(1, 20, 64)

y = x.squeeze(0)

print(y.shape)
# torch.Size([20, 64])
```

---

## 22. `squeeze()` Cannot Remove Real-Sized Axes

Suppose:

```text
x.shape = (8, 20, 64)
```

Axis 0 has eight positions.

It cannot be squeezed away because that would destroy actual structure.

`squeeze()` only removes dimensions whose size is exactly `1`.

Mental model:

```text
unsqueeze(n)
→ insert a size-1 axis at position n

squeeze(n)
→ remove axis n if it has size 1

squeeze()
→ remove all size-1 axes
```

---

## 23. Structural Operations vs Mathematical Operations

Keep these categories separate.

### Structural

```text
reshape
view
flatten
squeeze
unsqueeze
```

These mainly change how values are organized or interpreted.

### Mathematical

```text
+
-
*
/
@
```

These calculate with the values.

A structural change can affect a later mathematical result because it can change how dimensions line up, but the structural operation itself does not automatically alter the numerical values.

---

## 24. Day 3 Mental Model

```text
element-wise operation
→ matching positions interact

broadcasting
→ reuse a smaller compatible tensor across larger dimensions

reshape
→ reorganize the same number of values

view
→ reinterpret compatible underlying memory

flatten
→ collapse dimensions together

unsqueeze
→ add size-1 axis

squeeze
→ remove size-1 axis
```

The main rules to keep are:

```text
broadcasting:
compare from the right
same size OR one side is 1

reshape:
new dimensions must multiply to the same total element count
```

And the habit remains:

> Track the shape before and after every tensor operation.
