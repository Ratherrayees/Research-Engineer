# Tensors & Data — Day 4

## Axis Rearrangement, Matrix Multiplication, and AI Shape Reasoning

---

## 1. Why This Day Matters

So far, tensor work has focused on:

- understanding shape,
- selecting values,
- slicing ranges,
- broadcasting,
- reshaping,
- adding and removing axes.

The next step is learning how axes move and how tensors interact through matrix multiplication.

These ideas are central to:

- neural-network layers,
- embeddings,
- feature transformations,
- attention,
- Transformers.

The two major questions are:

```text
How do I rearrange axes?
```

and:

```text
How do I know whether matrix multiplication is valid and what shape it produces?
```

---

## 2. Matrix Transpose

For a 2D matrix, transpose swaps rows and columns.

Example:

```python
import torch

x = torch.tensor([
    [1, 2, 3],
    [4, 5, 6]
])

print(x.shape)
# torch.Size([2, 3])

y = x.transpose(0, 1)

print(y)
# tensor([
#     [1, 4],
#     [2, 5],
#     [3, 6]
# ])

print(y.shape)
# torch.Size([3, 2])
```

So:

```text
(2, 3)
↓ transpose
(3, 2)
```

This is the familiar school-level matrix transpose:

```text
rows ↔ columns
```

---

## 3. Transpose on Higher-Dimensional Tensors

In PyTorch, `transpose(a, b)` swaps exactly two axes.

Suppose:

```text
x.shape = (32, 50, 768)
```

where:

```text
axis 0 → batch/sentences
axis 1 → tokens
axis 2 → features
```

Then:

```python
y = x.transpose(1, 2)
```

swaps axes 1 and 2.

Result:

```text
(32, 768, 50)
```

Meaning:

```text
axis 0 → batch
axis 1 → features
axis 2 → tokens
```

The batch axis stayed where it was.

---

## 4. `permute()`

`permute()` is more general than `transpose()`.

Transpose says:

> Swap these two axes.

Permute says:

> Put all axes in this exact order.

Suppose:

```text
x.shape = (16, 100, 80)
```

with:

```text
0 → recordings
1 → time
2 → features
```

Then:

```python
y = x.permute(0, 2, 1)
```

means:

```text
old axis 0 first
old axis 2 second
old axis 1 third
```

Result:

```text
(16, 80, 100)
```

Meaning:

```text
recordings, features, time
```

---

## 5. Transpose vs Permute

The practical distinction is:

```text
transpose(a, b)
→ swap exactly two axes

permute(...)
→ specify the full new order of all axes
```

For a 3D tensor:

```python
x.transpose(1, 2)
```

and:

```python
x.permute(0, 2, 1)
```

can produce the same result.

But for more complicated rearrangements, `permute()` is clearer.

Example:

```text
x.shape = (10, 20, 30, 40)
```

To produce:

```text
(30, 10, 40, 20)
```

we can write:

```python
y = x.permute(2, 0, 3, 1)
```

The numbers are the old axis numbers in the order we want them to appear.

---

## 6. Permute Is Not Reshape

This distinction is important.

Suppose:

```text
x =
[[1, 2, 3],
 [4, 5, 6]]
```

Shape:

```text
(2, 3)
```

A reshape to `(3, 2)` can produce:

```text
[[1, 2],
 [3, 4],
 [5, 6]]
```

A transpose produces:

```text
[[1, 4],
 [2, 5],
 [3, 6]]
```

Both results have shape `(3, 2)`, but the values are arranged differently.

Mental model:

```text
reshape
→ regroup values according to the underlying order

transpose / permute
→ reorder axes
```

---

## 7. Element-Wise Multiplication vs Matrix Multiplication

Suppose:

```python
A = torch.tensor([
    [1.0, 2.0],
    [3.0, 4.0]
])

B = torch.tensor([
    [5.0, 6.0],
    [7.0, 8.0]
])
```

Element-wise multiplication:

```python
A * B
```

produces:

```text
[[ 5, 12],
 [21, 32]]
```

because matching positions are multiplied.

Matrix multiplication:

```python
A @ B
```

produces:

```text
[[19, 22],
 [43, 50]]
```

because rows of the first matrix combine with columns of the second.

These operations must never be confused.

---

## 8. Matrix Multiplication Shape Rule

Suppose:

```text
A.shape = (m, n)
B.shape = (n, p)
```

Then:

```text
A @ B
```

has shape:

```text
(m, p)
```

The inner dimensions must match:

```text
(m, n) @ (n, p)
     ↑     ↑
     must match
```

The outside dimensions survive:

```text
(m, p)
```

The rule is:

```text
(m, n) @ (n, p) → (m, p)
```

---

## 9. Why the Inner Dimensions Must Match

Take:

```text
(20, 64) @ (64, 8)
```

Each row of the first matrix contains 64 values.

Each column of the second matrix also contains 64 values.

Those matching lengths allow a row-column dot product.

The result contains:

```text
20 output rows
8 output columns
```

Therefore:

```text
(20, 8)
```

---

## 10. One Output Value Is a Dot-Product-Like Weighted Sum

Suppose one row is:

```text
[1, 2, 3]
```

and one column is:

```text
[7, 9, 11]
```

The output position is:

```text
1×7 + 2×9 + 3×11
```

which equals:

```text
58
```

So matrix multiplication repeatedly performs this row-column multiply-and-add process across many rows and columns.

This is why matrix multiplication connects naturally to neural-network weighted sums.

---

## 11. Valid and Invalid Shape Examples

Valid:

```text
(4, 8) @ (8, 16)
→ (4, 16)
```

because the inner `8`s match.

Valid:

```text
(20, 64) @ (64, 8)
→ (20, 8)
```

Invalid:

```text
(20, 64) @ (8, 64)
```

because:

```text
64 ≠ 8
```

The question is not:

```text
Do both matrices have the same shape?
```

The question is:

> Does the final dimension of the first 2D matrix match the first dimension of the second?

---

## 12. Square Matrices

A square matrix has the same number of rows and columns.

Examples:

```text
(2, 2)
(3, 3)
(64, 64)
```

This property is called being **square**.

Matrix multiplication does not require both matrices to be square.

For example:

```text
(20, 64) @ (64, 8)
```

is valid even though neither matrix is square.

---

## 13. Determinant Clarification

A determinant is a different linear-algebra concept.

For an ordinary square matrix such as:

```text
[[a, b],
 [c, d]]
```

its determinant is:

```text
ad - bc
```

The determinant produces one scalar value.

Important separation:

```text
square matrix
→ matrix with equal rows and columns

determinant
→ scalar associated with a square matrix

matrix multiplication
→ row-column combination governed by matching inner dimensions
```

A determinant is not used to make mismatched rectangular matrices multiply.

---

## 14. Matrix Multiplication in a Neural Network

Suppose one token is represented by:

```text
768 features
```

So:

```text
x.shape = (768,)
```

A neural-network layer wants to produce:

```text
3072 output features
```

The layer can contain a weight matrix:

```text
W.shape = (768, 3072)
```

Then:

```text
x @ W
```

has shape:

```text
(3072,)
```

Conceptually:

```text
768 input features
↓ learned weighted combinations
3072 output features
```

The token is still the same token, but its numerical representation has changed.

---

## 15. Higher-Dimensional Matrix Multiplication

Real AI tensors often contain extra leading dimensions.

Suppose:

```text
x.shape = (32, 50, 768)
```

meaning:

```text
32  samples/sentences
50  tokens per sample
768 features per token
```

and:

```text
W.shape = (768, 3072)
```

Then:

```python
y = x @ W
```

produces:

```text
y.shape = (32, 50, 3072)
```

The transformation acts on the final feature dimension.

So:

```text
(32, 50, 768)
         @
      (768, 3072)
          ↓
(32, 50, 3072)
```

The first two dimensions remain:

```text
32 samples
50 tokens
```

The feature dimension changes:

```text
768 → 3072
```

---

## 16. Why No Manual Loop Is Needed

There are:

```text
32 × 50 = 1600 tokens
```

inside the tensor.

Each token requires the same `768 → 3072` transformation.

We could imagine looping through all 1600 tokens, but tensor libraries perform the operation efficiently over the whole structure:

```python
y = x @ W
```

This is another example of expressing computation at the tensor level instead of manually iterating through every individual item.

---

## 17. What "Mixing Features" Means

Suppose one token has three input features:

```text
[x1, x2, x3]
```

One output feature may use learned weights:

```text
[w1, w2, w3]
```

and compute:

```text
x1w1 + x2w2 + x3w3
```

Another output feature uses a different set of weights.

So matrix multiplication lets every output feature be built from combinations of the input features.

This is much more expressive than element-wise multiplication, where each position interacts only with its matching position.

---

## 18. Adding Bias After Matrix Multiplication

A linear neural-network transformation is usually written conceptually as:

```text
y = xW + b
```

For:

```text
x.shape = (32, 50, 768)
W.shape = (768, 3072)
```

we get:

```text
x @ W → (32, 50, 3072)
```

The bias can have shape:

```text
b.shape = (3072,)
```

Then broadcasting allows:

```python
y = x @ W + b
```

The bias is reused across every token in every sample.

This connects Day 3 broadcasting directly to Day 4 matrix multiplication.

---

## 19. Complete Shape Walkthrough

Start with:

```text
x.shape = (32, 50, 768)
```

Meaning:

```text
32 samples
50 tokens
768 features
```

Select one sample:

```python
x[5]
```

Shape:

```text
(50, 768)
```

Select five samples:

```python
x[5:10]
```

Shape:

```text
(5, 50, 768)
```

Flatten batch and token axes:

```python
x.reshape(-1, 768)
```

Shape:

```text
(1600, 768)
```

Add one leading axis:

```python
x.unsqueeze(0)
```

Shape:

```text
(1, 32, 50, 768)
```

Swap token and feature axes:

```python
x.transpose(1, 2)
```

Shape:

```text
(32, 768, 50)
```

Explicitly reorder:

```python
x.permute(2, 0, 1)
```

Shape:

```text
(768, 32, 50)
```

Apply a learned feature transformation:

```python
y = x @ W
```

with:

```text
W.shape = (768, 3072)
```

Result:

```text
(32, 50, 3072)
```

## 20. Structural vs Mathematical Thinking

A useful final distinction is:

### Structural operations

```text
index
slice
reshape
flatten
squeeze
unsqueeze
transpose
permute
```

These answer questions such as:

```text
Which data do I want?
How should the axes be arranged?
What shape should this data have?
```

### Mathematical operations

```text
+
-
*
/
@
```

These answer:

```text
What calculation should happen to the values?
```

Both kinds of reasoning are required in AI.

## 21. Day 4 Mental Model

```text
transpose
→ swap two axes

permute
→ specify complete axis order

A * B
→ element-wise multiplication

A @ B
→ matrix multiplication

(m, n) @ (n, p)
→ (m, p)
```

For higher-dimensional AI tensors:

```text
(batch, sequence, input_features)
@
(input_features, output_features)
→
(batch, sequence, output_features)
```

Example:

```text
(32, 50, 768)
@
(768, 3072)
→
(32, 50, 3072)
```

The key habit is:

> Before running any tensor operation, identify what every axis represents and predict the output shape.

That habit is more valuable than memorizing tensor syntax.
