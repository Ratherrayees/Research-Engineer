# Day 1 - Why LLMs Need Numbers

## Objective

Understand why language models cannot process raw text and why tokenization exists.

## Traditional Programming

- Programmer writes rules.
- Computer executes them.
- Suitable for deterministic problems.

## Machine Learning

Instead of writing rules manually, we build a model that learns patterns from examples.

## Model

A model is a mathematical function that maps input to output.

Example:

prediction = input × w

where `w` is a learnable parameter.

## Tokenization

LLMs cannot process text directly.

Text

↓

Tokens

↓

Token IDs

↓

Embeddings

↓

Transformer

## Token IDs

Token IDs are identifiers only.

Example:

I → 1
love → 2
AI → 3

The numbers themselves carry no meaning.

## Vocabulary

The vocabulary is the mapping from tokens to IDs.

Once training begins, these IDs remain fixed because the embedding table depends on them.

## Embeddings

Instead of representing a token as a single integer, we represent it as a high-dimensional vector.

Example:

dog →

[0.18, -0.42, 0.91, ...]

Initially these vectors are random.

Training gradually adjusts them into meaningful representations.

## Key Takeaways

- Computers process numbers, not language.
- Token IDs are labels.
- Embeddings are learnable numerical representations.
- Similarity in embedding space is learned, not manually programmed.
