# Math for AI — Day 2

## Algebra, Relationships, Equations, Functions, and Input → Output Thinking

---

# 1. What Day 2 Is About

Day 1 introduced the basic language of mathematics:

* Quantities
* Variables
* Constants
* Parameters
* Expressions
* Equations
* Multiplication as scaling
* Division as relative comparison
* The basic AI structure:

[
z=wx+b
]

Day 2 goes one level deeper.

The main goal is to understand:

> How mathematical quantities depend on one another.

This idea is fundamental to AI.

A neural network is not just a giant collection of numbers.

It is a giant system of **dependencies**.

One quantity affects another quantity, which affects another quantity, which eventually affects the final output.

Very roughly:

[
\text{input}
\rightarrow
\text{computation}
\rightarrow
\text{intermediate values}
\rightarrow
\text{prediction}
]

During training:

[
\text{prediction}
\rightarrow
\text{loss}
]

And later we will ask:

> Which earlier quantities were responsible for changing that loss?

Before reaching that point, we need to become comfortable with algebraic relationships.

---

# 2. Variables Represent Quantities

Recall:

[
x
]

is simply a name for some quantity.

Suppose:

[
x=5
]

Then wherever (x) appears, we can substitute 5.

For example:

[
2x+3
]

becomes:

[
2(5)+3
]

which gives:

[
13
]

So an expression containing variables can produce different values depending on the values assigned to those variables.

If:

[
x=2
]

then:

[
2x+3=7
]

If:

[
x=10
]

then:

[
2x+3=23
]

The mathematical rule did not change.

Only the input value changed.

This is the foundation of **general mathematical relationships**.

---

# 3. A Variable Is Not Always an Unknown

In school algebra, (x) is often introduced as:

> The mysterious number you need to find.

For example:

[
x+4=10
]

Here, (x) is indeed an unknown.

We solve:

[
x=6
]

But that is only one way variables are used.

Consider:

[
y=2x+3
]

Here, (x) does not have one secret correct value.

It can take many values.

For example:

[
x=0
]

gives:

[
y=3
]

while:

[
x=1
]

gives:

[
y=5
]

and:

[
x=10
]

gives:

[
y=23
]

So here:

[
x
]

represents an **input quantity that can vary**.

This distinction is very important for AI.

Model inputs are usually variables, not mystery numbers waiting to be solved.

---

# 4. Dependent and Independent Quantities

Consider:

[
y=2x+3
]

The value of (y) depends on the value of (x).

Change (x), and (y) changes.

Therefore:

[
x
]

can be thought of as an **independent/input variable**, while:

[
y
]

is a **dependent/output variable**.

Why?

Because (y)'s value depends on (x).

So:

[
\boxed{x \rightarrow y}
]

means:

> Changes in (x) can produce changes in (y).

This idea of dependency becomes extremely important later.

---

# 5. Reading Equations as Processes

Consider:

[
y=3x+2
]

Do not read this only as:

> y equals three x plus two.

Instead, mentally execute it as a process.

Start with:

[
x
]

Then multiply by 3:

[
3x
]

Then add 2:

[
3x+2
]

Then call the result:

[
y
]

So the equation describes:

[
x
\xrightarrow{\times3}
3x
\xrightarrow{+2}
y
]

This way of reading mathematics will become extremely valuable for neural networks.

---

# 6. Expressions Are Computation Instructions

Consider:

[
5x+4
]

This expression tells us to:

1. Take (x)
2. Multiply it by 5
3. Add 4

If:

[
x=3
]

then:

[
5(3)+4
]

which gives:

[
19
]

So expressions can be understood as little computation programs.

For example:

[
wx+b
]

can be interpreted like:

```text
take x
multiply it by w
add b
return the result
```

This is already very close to how computation is represented in machine learning code.

---

# 7. Terms

Consider:

[
3x+5y+7
]

This expression contains three **terms**:

[
3x
]

[
5y
]

and:

[
7
]

Terms are pieces of an expression separated by addition or subtraction.

Understanding terms helps us break complicated expressions into smaller parts.

For example:

[
w_1x_1+w_2x_2+w_3x_3+b
]

contains the terms:

[
w_1x_1
]

[
w_2x_2
]

[
w_3x_3
]

and:

[
b
]

Each weighted input contributes one term.

The terms are then added together.

This structure appears constantly in neural networks.

---

# 8. Coefficients

Consider:

[
5x
]

The number:

[
5
]

is called the **coefficient** of (x).

It tells us how much (x) is being scaled.

For example:

[
2x
]

scales (x) by 2.

[
0.5x
]

scales (x) by one-half.

[
-3x
]

scales (x) by 3 and reverses the sign.

In machine learning, a weight often plays the role of a coefficient.

For example:

[
wx
]

Here:

[
w
]

acts as the coefficient of (x).

But unlike a fixed number such as 5, (w) may be learned during training.

---

# 9. Subscripts

AI equations often contain symbols such as:

[
x_1,x_2,x_3
]

or:

[
w_1,w_2,w_3
]

The small number at the bottom is called a **subscript**.

It does not mean multiplication.

For example:

[
x_2
]

does NOT mean:

[
x\times2
]

Instead, it usually means:

> the second (x)-type quantity.

Suppose a model receives three input features:

[
x_1=\text{temperature}
]

[
x_2=\text{humidity}
]

[
x_3=\text{wind speed}
]

The subscripts allow us to distinguish between different inputs of the same general type.

Likewise:

[
w_1,w_2,w_3
]

can represent different weights.

---

# 10. Multiple Inputs

A simple relationship might use one input:

[
z=wx+b
]

But real models usually receive many inputs.

Suppose there are three inputs:

[
x_1,x_2,x_3
]

Each input may have its own weight:

[
w_1,w_2,w_3
]

Then the computation could be:

[
z=w_1x_1+w_2x_2+w_3x_3+b
]

This equation looks larger, but conceptually it is still simple.

For each input:

[
x_i
]

we scale it using its weight:

[
w_ix_i
]

Then we add all the contributions:

[
w_1x_1+w_2x_2+w_3x_3
]

Then add the bias:

[
+b
]

So:

[
\boxed{
z=
\text{weighted input 1}
+
\text{weighted input 2}
+
\text{weighted input 3}
+
\text{bias}
}
]

This is much closer to what a real neuron does.

---

# 11. Why Different Inputs Need Different Weights

Suppose a model uses several pieces of information.

Some inputs might strongly matter for the prediction.

Others might matter only slightly.

The model therefore needs a way to control each contribution separately.

That is the job of weights.

For example:

[
z=w_1x_1+w_2x_2
]

If:

[
w_1=5
]

and:

[
w_2=0.1
]

then changes in (x_1) generally have a much stronger direct effect on (z) than similar changes in (x_2), assuming comparable input scales.

This is one of the reasons neural networks contain enormous numbers of parameters.

They need many adjustable values controlling many relationships.

---

# 12. Solving Equations

Now consider:

[
x+5=12
]

We want to determine the value of (x).

The goal is to **isolate (x)**.

Start:

[
x+5=12
]

Subtract 5 from both sides:

[
x+5-5=12-5
]

which gives:

[
x=7
]

The important idea is:

> We performed the same operation on both sides.

Equality remained preserved.

---

# 13. Undoing Operations

Solving equations often means reversing operations.

Consider:

[
x+5=12
]

The operation applied to (x) was:

[
+5
]

The inverse operation is:

[
-5
]

So we subtract 5.

---

Consider:

[
3x=15
]

The operation applied to (x) was multiplication by 3.

The inverse operation is division by 3.

So:

[
\frac{3x}{3}
============

\frac{15}{3}
]

giving:

[
x=5
]

The general idea is:

[
\boxed{\text{Solving often means undoing operations in reverse}}
]

---

# 14. Inverse Operations

Common inverse pairs are:

Addition and subtraction:

[
+5 \leftrightarrow -5
]

Multiplication and division:

[
\times5 \leftrightarrow \div5
]

Later we will encounter more inverse relationships:

[
\text{squaring} \leftrightarrow \text{square root}
]

and:

[
\text{exponentiation} \leftrightarrow \text{logarithm}
]

Understanding inverse operations will therefore become very important.

---

# 15. Solving a Two-Step Equation

Consider:

[
2x+3=11
]

We want (x) alone.

The expression tells us that two operations happened to (x):

1. Multiply by 2
2. Add 3

To isolate (x), undo those operations in reverse order.

First undo:

[
+3
]

by subtracting 3:

[
2x+3-3=11-3
]

giving:

[
2x=8
]

Now undo:

[
\times2
]

by dividing by 2:

[
\frac{2x}{2}
============

\frac{8}{2}
]

giving:

[
x=4
]

Notice what happened.

Forward:

[
x
\xrightarrow{\times2}
2x
\xrightarrow{+3}
11
]

To solve backward:

[
11
\xrightarrow{-3}
8
\xrightarrow{\div2}
4
]

This forward/backward way of thinking becomes useful much later when we discuss computation graphs and backpropagation.

---

# 16. Rearranging Equations

Sometimes we are not trying to discover a mystery number.

Instead, we want to express one variable in terms of another.

Suppose:

[
y=2x+4
]

and we want (x) by itself.

Start:

[
y=2x+4
]

Subtract 4:

[
y-4=2x
]

Then divide by 2:

[
x=\frac{y-4}{2}
]

Now we have expressed (x) in terms of (y).

This is called **rearranging an equation**.

The relationship itself has not changed.

We have simply written it from another perspective.

---

# 17. Why Rearranging Matters

In AI mathematics, we often know several related quantities and want to isolate one particular one.

Being able to rearrange equations lets us reason about relationships rather than memorizing a separate formula for every situation.

Instead of memorizing ten formulas, it is often better to understand one relationship and know how to rearrange it.

---

# 18. What Is a Function?

A **function** is a rule that takes input and produces output.

Consider:

[
f(x)=2x+3
]

This says:

> There is a function called (f).

> It receives (x).

> It multiplies (x) by 2.

> It adds 3.

> It returns the result.

So conceptually:

[
x
\rightarrow
f
\rightarrow
\text{output}
]

or more specifically:

[
x
\rightarrow
2x+3
\rightarrow
f(x)
]

---

# 19. What Does (f(x)) Mean?

This notation:

[
f(x)
]

does NOT mean:

[
f\times x
]

The parentheses have a different meaning.

They mean:

> Give (x) to the function (f).

So if:

[
f(x)=2x+3
]

then:

[
f(5)
]

means:

> Give the value 5 to the function.

Replace (x) with 5:

[
f(5)=2(5)+3
]

which gives:

[
f(5)=13
]

---

# 20. Function Names Are Arbitrary

The function does not have to be called (f).

We could define:

[
g(x)=x+10
]

or:

[
h(x)=x^2
]

or even:

[
\text{cost}(x)=5x+100
]

The function name simply identifies which rule we are talking about.

---

# 21. Functions Are Like Reusable Computations

Suppose:

[
f(x)=3x+2
]

Instead of repeatedly writing:

[
3x+2
]

we can refer to the entire rule as:

[
f
]

Then:

[
f(1)=5
]

[
f(2)=8
]

[
f(10)=32
]

Same function.

Different inputs.

Different outputs.

A function therefore represents a reusable mathematical transformation.

---

# 22. Input → Transformation → Output

The most useful mental model for functions is:

[
\boxed{
\text{input}
\rightarrow
\text{transformation}
\rightarrow
\text{output}
}
]

For:

[
f(x)=2x+3
]

we have:

[
x
\rightarrow
2x+3
\rightarrow
f(x)
]

This structure appears everywhere in AI.

---

# 23. An AI Model Can Be Viewed as a Function

Very abstractly, a machine-learning model can be represented as:

[
y=f(x)
]

where:

[
x=\text{input}
]

[
f=\text{model}
]

[
y=\text{output}
]

For an image model:

[
\text{prediction}
=================

\text{model}(\text{image})
]

For a language model:

[
\text{next-token probabilities}
===============================

\text{model}(\text{previous tokens})
]

The real function may contain billions of operations, but the basic idea remains:

[
\boxed{\text{input}\rightarrow\text{model}\rightarrow\text{output}}
]

---

# 24. Functions Can Have Multiple Inputs

A function does not need only one input.

For example:

[
f(x,y)
]

means the function receives both:

[
x
]

and:

[
y
]

Suppose:

[
f(x,y)=2x+3y
]

Then:

[
f(4,5)
]

means:

[
2(4)+3(5)
]

which gives:

[
8+15=23
]

So:

[
f(4,5)=23
]

Machine-learning models almost always operate on many values at once.

---

# 25. Intermediate Variables

Consider this sequence:

[
z=2x+3
]

and then:

[
y=z^2
]

Here, (z) is an **intermediate value**.

The full process is:

[
x
\rightarrow
z
\rightarrow
y
]

Suppose:

[
x=2
]

Then:

[
z=2(2)+3=7
]

Then:

[
y=7^2=49
]

So information flowed through multiple calculations.

This is very important.

Neural networks contain huge numbers of intermediate values.

---

# 26. Chaining Functions

Suppose:

[
f(x)=2x
]

and:

[
g(x)=x+3
]

We can apply (f) first.

If:

[
x=5
]

then:

[
f(5)=10
]

Now use that result as input to (g):

[
g(10)=13
]

So:

[
5
\rightarrow
10
\rightarrow
13
]

One function's output becomes another function's input.

This is called **function composition** or function chaining.

---

# 27. Function Composition Notation

You may eventually encounter:

[
g(f(x))
]

Read it from the inside outward.

First calculate:

[
f(x)
]

Then feed that result into:

[
g
]

If:

[
f(x)=2x
]

and:

[
g(x)=x+3
]

then:

[
g(f(x))
]

means:

[
g(2x)
]

Since (g) adds 3:

[
g(f(x))=2x+3
]

You do not need to memorize this notation yet.

The important idea is simply:

[
\boxed{\text{output of one computation can become input to another}}
]

---

# 28. Neural Networks Are Chains of Functions

A neural network contains many stages.

Very roughly:

[
x
\rightarrow
f_1
\rightarrow
f_2
\rightarrow
f_3
\rightarrow
y
]

Each stage transforms the information.

For example:

[
x
\rightarrow
z_1
\rightarrow
a_1
\rightarrow
z_2
\rightarrow
a_2
\rightarrow
y
]

At first this looks complicated.

But structurally, it is still:

[
\text{input}
\rightarrow
\text{transformation}
\rightarrow
\text{transformation}
\rightarrow
\text{output}
]

Understanding this now will make neural-network mathematics much easier later.

---

# 29. Dependency Chains

Suppose:

[
z=2x
]

and:

[
y=z+5
]

Then (y) depends on (z).

But (z) depends on (x).

Therefore (y) indirectly depends on (x).

The dependency chain is:

[
x\rightarrow z\rightarrow y
]

So changing (x) can eventually change (y).

This concept becomes one of the central ideas of calculus and backpropagation.

Later we will ask:

> If (x) changes slightly, how much does (z) change?

And:

> If (z) changes slightly, how much does (y) change?

Then:

> How much does (y) ultimately respond to a change in (x)?

That will eventually lead to the **chain rule**.

But for now, simply understand the dependency.

---

# 30. Parameters Inside Functions

A more realistic model function might be written:

[
f(x;w,b)
]

The notation is sometimes used to distinguish:

* (x) = input
* (w,b) = parameters

You do not need to worry about the semicolon notation yet.

The important idea is that a model's output depends on both:

1. The input data
2. The model parameters

So we can think:

[
\text{output}
=============

f(\text{input},\text{parameters})
]

If the input changes, the output may change.

If the parameters change, the output may also change.

This is exactly why training can work.

Training changes the parameters in order to change the model's future outputs.

---

# 31. The Core Machine-Learning Relationship

At a very high level:

[
\text{input}
\rightarrow
\text{model parameters}
\rightarrow
\text{prediction}
]

During training, we compare the prediction with the desired answer.

So:

[
\text{input}
\rightarrow
\text{model}
\rightarrow
\text{prediction}
\rightarrow
\text{error/loss}
]

Training then needs to determine:

> Which model parameters should change?

and:

> How should they change?

That problem will eventually require derivatives and gradients.

But those ideas make sense only after understanding dependency relationships.

---

# 32. A Simple Computation Chain

Consider:

[
z=wx+b
]

and suppose:

[
x=4
]

[
w=2
]

[
b=3
]

Then:

[
z=2(4)+3
]

giving:

[
z=11
]

The dependency structure is:

[
x\rightarrow wx\rightarrow wx+b\rightarrow z
]

But notice:

[
z
]

also depends on:

[
w
]

and:

[
b
]

So more accurately:

```text
x ──┐
    ├── multiplication ──┐
w ──┘                    │
                         ├── addition ── z
b ───────────────────────┘
```

This is the beginning of what we will later call a **computation graph**.

---

# 33. Why Computation Graph Thinking Matters

A complicated neural network may contain millions or billions of operations.

Trying to understand it as one gigantic formula would be nearly impossible.

Instead, we can break the computation into small steps.

For example:

[
a=wx
]

then:

[
z=a+b
]

Now:

[
z=wx+b
]

has been broken into:

[
x,w
\rightarrow
a
\rightarrow
z
]

This makes dependencies visible.

Later, backpropagation will travel backward through these dependency relationships.

So computation-graph thinking is not merely a visualization trick.

It reflects how machine-learning systems actually organize calculations.

---

# 34. The Difference Between a Formula and Understanding

Suppose someone gives you:

[
z=w_1x_1+w_2x_2+b
]

You could memorize this as:

> Multiply weights and inputs, add them, add bias.

But understanding means seeing:

[
x_1
\xrightarrow{\times w_1}
w_1x_1
]

and:

[
x_2
\xrightarrow{\times w_2}
w_2x_2
]

then:

[
w_1x_1+w_2x_2
]

then:

[
+b
]

then:

[
z
]

So the full process is:

[
\boxed{
\text{independent contributions}
\rightarrow
\text{combined contribution}
\rightarrow
\text{bias}
\rightarrow
\text{output}
}
]

That is the level of understanding we want throughout this course.

# Day 2 Mental Model

The most important idea from Day 2 is:

[
\boxed{\text{Mathematics describes chains of dependency}}
]

A value does not exist in isolation.

Suppose:

[
z=wx+b
]

Then:

[
z
]

depends on:

[
x,w,b
]

If any of these values changes, (z) may change.

Now suppose:

[
y=f(z)
]

Then:

[
y
]

depends on (z).

But because (z) depends on (w):

[
w\rightarrow z\rightarrow y
]

Therefore changing (w) can ultimately change (y).

This idea becomes absolutely central to neural-network training.

Eventually, the mathematical question becomes:

> If I change (w) slightly, how much will (y) change?

And later:

> If (y) determines the loss, how much will changing (w) change the loss?

That question is where calculus begins.

But before calculus, we need to become comfortable **seeing mathematical relationships visually**, which is where graphs, coordinates, slope, and rate of change enter the picture.
