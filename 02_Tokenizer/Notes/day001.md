# Day 001 — Tokenizer Notes

## Goal

Build a very basic tokenizer from scratch and understand the first important steps in converting text into numbers.

The tokenizer should:

1. Split a sentence into tokens.
2. Build a vocabulary.
3. Assign integer IDs to unique tokens.
4. Convert the sentence into token IDs.
5. Convert those IDs back into tokens.

---

# 1. Input Text

We start with normal human-readable text:

Hello, AI Engineer! I love AI

A machine learning model cannot directly work with this sentence as meaningful text.

It ultimately needs numerical representations.

So the first job is to convert the text into smaller units.

---

# 2. Splitting the Sentence into Tokens

We split the sentence using spaces.

This produces:

Hello,

AI

Engineer!

I

love

AI

Each piece is treated as one token.

So:

Text

↓

Tokens

In our simple tokenizer:

token = one whitespace-separated piece of text

Important:

This means punctuation stays attached.

For example:

Hello,

is treated as one token, including the comma.

Engineer!

is also one token, including the exclamation mark.

---

# 3. Building a Vocabulary

Next, we create a vocabulary.

The vocabulary stores every unique token and assigns it an integer ID.

Conceptually:

token → ID

For our sentence, the vocabulary becomes approximately:

Hello, → 0

AI → 1

Engineer! → 2

I → 3

love → 4

Notice that AI appears twice in the sentence.

But it only appears once in the vocabulary.

This is because the vocabulary stores unique tokens.

---

# 4. Why Repeated Tokens Use the Same ID

The token:

AI

appears two times.

Both occurrences receive the same ID.

If:

AI → 1

then every occurrence of AI becomes:

1

This is important because the tokenizer needs a consistent mapping.

The same token should not randomly receive different IDs.

So:

same token → same ID

---

# 5. Assigning Integer IDs

We assign IDs based on the current size of the vocabulary.

Conceptually:

First unique token → 0

Second unique token → 1

Third unique token → 2

and so on.

The integer ID is not the meaning of the word.

For example:

AI → 1

does not mean that the mathematical number 1 somehow represents the concept of artificial intelligence.

It is simply an identifier.

Think of it like an index or address inside the vocabulary.

---

# 6. Encoding

Encoding means converting tokens into their integer IDs.

Our token sequence is:

Hello,

AI

Engineer!

I

love

AI

Using the vocabulary, this becomes approximately:

0

1

2

3

4

1

So the full transformation is:

Text

↓

Tokens

↓

Token IDs

This is called encoding.

---

# 7. Why Token IDs Matter

The model does not work directly with strings such as:

"AI"

Instead, the tokenizer gives the model an integer ID.

So we begin moving from:

human language

to:

numbers

However, the token ID itself is still not enough for a neural network.

Later, the token ID will be used to retrieve an embedding vector.

The larger pipeline will eventually become:

Text

↓

Tokens

↓

Token IDs

↓

Embeddings

↓

Neural Network

But on Day 001, we are only focusing on the tokenizer part.

---

# 8. Decoding

Decoding performs the reverse operation.

We already have:

token → ID

Now we want:

ID → token

Our Day 001 implementation does this by searching through the vocabulary.

For each token ID:

1. Look through the vocabulary values.
2. Find where that ID appears.
3. Find the token at the same position.
4. Return that token.

So if:

AI → 1

then when decoding ID:

1

we recover:

AI

---

# 9. The Full Day 001 Pipeline

Our tokenizer now performs:

Original sentence

↓

Split into tokens

↓

Build vocabulary

↓

Assign IDs

↓

Encode tokens into IDs

↓

Decode IDs back into tokens

So conceptually:

Text → Tokens → IDs → Tokens

---

# 10. What the Output Proves

If the output shows:

Original sentence:
Hello, AI Engineer! I love AI

Tokens:
['Hello,', 'AI', 'Engineer!', 'I', 'love', 'AI']

Vocabulary:
{'Hello,': 0, 'AI': 1, 'Engineer!': 2, 'I': 3, 'love': 4}

Token IDs:
[0, 1, 2, 3, 4, 1]

Decoded tokens:
['Hello,', 'AI', 'Engineer!', 'I', 'love', 'AI']

then the tokenizer successfully performed both:

Encoding:
text → IDs

and:

Decoding:
IDs → tokens

---

# Important Concepts Learned

## Token

A smaller unit of text produced by the tokenizer.

In our Day 001 tokenizer, tokens are created by splitting the sentence on spaces.

---

## Vocabulary

A collection of unique tokens and their IDs.

It maps:

token → ID

---

## Token ID

An integer identifier assigned to a token.

It does not itself contain the meaning of the token.

---

## Encoding

Converting:

tokens → token IDs

---

## Decoding

Converting:

token IDs → tokens

---

# Limitation of Our Day 001 Decoder

Our decoder works, but it is inefficient.

To decode every ID, it searches through the vocabulary to find the corresponding token.

Conceptually:

ID

↓

Search all vocabulary values

↓

Find matching position

↓

Find corresponding token

This works for our tiny vocabulary.

But if the vocabulary had tens of thousands of tokens, repeatedly searching through it would be wasteful.

This limitation leads directly into the Day 002 improvement:

Create a reverse vocabulary:

ID → token

so decoding can become a direct lookup instead of a search.

---

# Another Limitation

Because we split only on spaces:

Hello

and:

Hello,

would be treated as different tokens.

Likewise:

AI

AI,

AI.

would all be different vocabulary entries.

We do not solve that problem yet.

For Day 001, the goal is simply to understand the fundamental tokenizer pipeline.

---

# Core Mental Model

A tokenizer acts as a bridge between human-readable text and numerical IDs.

The most important idea from Day 001 is:

Text is not directly given to the model.

It first becomes:

Text → Tokens → Token IDs

And later, those IDs will be converted into numerical vectors called embeddings.
