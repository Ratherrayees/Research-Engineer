# Day 002 — Tokenizer Notes

## Goal

Build a basic tokenizer from scratch that can:

1. Split a sentence into tokens.
2. Build a vocabulary.
3. Assign integer IDs to unique tokens.
4. Encode tokens into IDs.
5. Decode IDs back into tokens.
6. Reconstruct the original sentence.
7. Use a reverse vocabulary for efficient decoding.

---

## 1. Input Sentence

We start with a normal sentence:

Hello, AI Engineer! I love AI, and I am excited to learn more about AI.

The tokenizer cannot work directly with the sentence as one big string.

So the first step is to split it into smaller pieces.

---

## 2. Splitting the Sentence into Tokens

We use whitespace splitting.

This produces tokens like:

Hello,
AI
Engineer!
I
love
AI,
and
I
am
excited
to
learn
more
about
AI.

Important observation:

AI

AI,

and

AI.

are treated as different tokens because punctuation remains attached.

So this is a very simple word-level tokenizer.

---

## 3. Building the Vocabulary

The vocabulary stores every unique token.

It works like:

token → integer ID

For example:

Hello, → 0

AI → 1

Engineer! → 2

I → 3

love → 4

If a token appears multiple times, it is only added once.

For example:

I

appears more than once, but it still has only one vocabulary ID.

---

## 4. Assigning Integer IDs

Each unique token receives an integer ID.

The ID is created based on the current vocabulary size.

Conceptually:

First unique token → 0

Second unique token → 1

Third unique token → 2

and so on.

The integer itself does not contain the meaning of the word.

It simply identifies that token inside the vocabulary.

---

## 5. Encoding

Encoding means:

tokens → token IDs

For every token in the sentence, we look up its ID inside the vocabulary.

For example:

I → 3

So every time the tokenizer sees I, it stores:

3

The sentence is therefore converted from human-readable text into a sequence of integers.

Conceptually:

Text

↓

Tokens

↓

Token IDs

---

## 6. Reverse Vocabulary

The normal vocabulary works like:

token → ID

But during decoding, we need the opposite:

ID → token

So we create a reverse vocabulary.

Example:

Normal vocabulary:

AI → 1

Reverse vocabulary:

1 → AI

This lets us directly retrieve a token using its ID.

---

## 7. Why Reverse Vocabulary Is Better

Originally, we could decode an ID by:

1. Searching through all vocabulary values.
2. Finding where the ID exists.
3. Looking at the token at the corresponding position.

That works, but it is unnecessarily indirect.

With reverse vocabulary:

ID → token

is a direct lookup.

So we now have:

Encoding:

token → ID

Decoding:

ID → token

---

## 8. Decoding

Decoding converts:

token IDs → tokens

For every ID in the encoded sentence, we look it up inside the reverse vocabulary.

Example:

3 → I

1 → AI

This recreates the original sequence of tokens.

---

## 9. Reconstructing the Sentence

After decoding, we have a list of tokens.

We then join those tokens together using spaces.

So:

Decoded tokens

↓

Join with spaces

↓

Reconstructed sentence

The reconstructed sentence becomes:

Hello, AI Engineer! I love AI, and I am excited to learn more about AI.

This matches the original input sentence.

---

# Complete Pipeline

Our Day 002 tokenizer now works like this:

Original text

↓

Split into tokens

↓

Build vocabulary

↓

Assign integer IDs

↓

Encode tokens into IDs

↓

Create reverse vocabulary

↓

Decode IDs into tokens

↓

Join tokens

↓

Reconstructed text

---

# Important Things Learned

## Token

A token is one unit produced by the tokenizer.

In our tokenizer, tokens are created by splitting on spaces.

---

## Vocabulary

A mapping of:

token → ID

It stores every unique token.

---

## Token ID

An integer that represents a token inside the vocabulary.

The integer itself does not contain the meaning of the token.

---

## Encoding

Converting:

tokens → IDs

---

## Decoding

Converting:

IDs → tokens

---

## Reverse Vocabulary

A mapping of:

ID → token

It makes decoding simple and direct.

---

# Limitation Discovered

Our tokenizer treats punctuation as part of the token.

So:

AI

AI,

AI.

become three separate vocabulary entries.

This means our tokenizer is useful for understanding the basic mechanism, but it is not how modern LLM tokenizers usually work.

This limitation leads into Day 003, where we study subword tokenization and why algorithms such as BPE are used.
